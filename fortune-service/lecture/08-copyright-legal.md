# 08강. 저작권과 법적 체크

> ⚠ 이 강의는 일반적인 기준을 정리한 것이며 법률 자문이 아니다. 수익을 낼 계획이면 전문가 확인을 받을 것.

## 학습 목표
- 무엇이 보호되고 무엇이 자유롭게 쓸 수 있는지 구분한다
- 공개 전에 체크할 항목을 안다

---

## 1. 보호되는 것 vs 아닌 것

| 대상 | 보호? | 우리 프로젝트 |
|---|---|---|
| 문장 표현 (운세·해몽 원문) | ✅ 보호 | 전부 새로 씀 + 유사도 검사 |
| 아이디어·민간 상식 ("돼지꿈 = 재물") | ❌ | 의미만 참고 |
| 계산 결과·사실 (사주팔자, 날짜) | ❌ | 정답셋으로 사용 |
| 레이아웃 구성 (카드 배치) | ❌ (일반적으로) | 구조만 참고 |
| 로고·브랜드 색·고유 디자인 | ✅ | 사용 안 함 |
| 1909 라이더-웨이트 타로 | ❌ 퍼블릭 도메인 (작가 1951년 사망 + 70년) | 사용 |
| manseryeok (MIT), 폰트 (OFL) | 라이선스 준수 | 출처 표기 |

## 2. 크롤링의 위험 지점
- **데이터베이스 제작자 권리** (저작권법 제93조): 상당 부분을 체계적으로 복제하면 문제
- **이용약관**: 자동 수집 금지 조항
- → 소량·저빈도로, 원문은 공개하지 않는다

## 3. 개인정보
- 생년월일·꿈 일기를 **서버로 보내지 않음** → "수집"하지 않는 구조
- 로그인·분석·서버 저장을 붙이는 순간 개인정보처리방침 필요

## 4. 표현 주의 (면책)
피해야 할 표현:
- 건강운 → 의학적 단정 ("병이 생긴다")
- 재물운 → 투자 조언 ("주식을 사라")
- 로또 → 당첨 보장

넣은 것:
- 모든 페이지 푸터: "재미를 위한 콘텐츠이며 의학·투자·법률 등 전문적인 조언을 대신하지 않아요"
- `/terms` 이용 안내: 오락 목적, 책임의 한계, 저장 방식, 출처·라이선스

## 5. 공개 저장소의 함정 ⭐

사이트는 깨끗해도 **공개 저장소**에는 이런 게 같이 보인다:
- 어떤 사이트를 어떻게 긁었는지 (크롤러 코드)
- 참고 사이트 목록 (REFERENCES.md)

→ **소스 저장소는 비공개, 빌드된 사이트만 공개 저장소로** 분리했다 (09강).

## 정리
- 표현은 보호, 아이디어·사실은 자유
- 원문은 로컬에만, 공개 저장소에는 결과물만
- 개인정보는 안 모으는 게 최선
- 면책은 푸터 + 이용 안내 두 군데에
