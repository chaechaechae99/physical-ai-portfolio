# 02강. 기획과 계획서

## 학습 목표
- 막연한 아이디어를 기능 목록·우선순위·로드맵으로 바꾼다
- "데이터를 어디서 얻을 것인가"를 기획 단계에서 결정한다

---

## 1. 필요한 질문 6가지

계획서를 쓰기 전에 사용자에게 물은 것:

| 질문 | 답 |
|---|---|
| 서비스 형태 | 웹사이트 |
| 핵심 기능 | 재물운, 미래 배우자, 오늘의 운세 (+ 로또) |
| 데이터 방식 | 알아서 (→ 추천안 결정) |
| 대상 | 2030 |
| 수익 모델 | 없음 (공부용) |
| 계획서 형식 | 알아서 (→ `PLAN.md`) |

> 모르는 건 "모름"으로 받고 **추천안을 넣는다**. 질문을 위한 질문은 하지 않는다.

## 2. 기능은 대화하며 자란다

| 단계 | 기능 수 | 변화 |
|---|---|---|
| 1차 | 3 | 로또운·재물운·배우자 |
| 2차 | 4 | 로또**운** → 로또 **랜덤 뽑기**(게임), 오늘의 운세 추가 |
| 3차 | 12 | 진지 모드(궁합·주간·월간·신년·평생) + 재미 모드(타로·전생·**꿈해몽**) |
| 4차 | 15 | 꿈 일기장·별자리·띠별 추가 |

교훈:
- "운"이라고 부르면 진지해진다 → 로또는 게임으로 분리
- **꿈해몽**은 10~90대 모두 찾는 키워드 → 홈 최상단 검색창으로
- 꿈 일기장은 **재방문 장치**

## 3. 카테고리 이름도 기획이다

`진지 모드 / 재미 모드` → `운세 / 신비`. 짧고, 서로 대비되고, 섹션 제목으로 바로 쓸 수 있는 이름.

## 4. 가장 중요한 결정: 데이터 방식

```
[수집·분석]          [자체 엔진]                [서비스]
크롤러       →   사주 계산 + 문장 생성   →   웹사이트
(구조·정답셋)        (직접 작성)               (재작성본만)
```

**"크롤링은 참고용, 서비스는 자체 생성"**
- 남의 문장을 그대로 서비스 → 저작권·약관 문제
- 계산 결과(사주팔자)는 사실 → **정답셋**으로 활용
- 사주 로직을 직접 구현하는 것이 공부의 핵심

## 5. 우선순위와 로드맵

| 단계 | 내용 |
|---|---|
| M0 | 폴더 구조, 레퍼런스 |
| M1 | 데이터 수집 |
| M2 | 홈 + 입력 없는 재미 기능 (빠르게 화면 보기 = 동기부여) |
| M3 | 꿈해몽 |
| M4 | 사주 엔진 |
| M5 | 운세 문장 생성 |
| M6 | 결과 카드 공유 |
| M8 | 배포 |

> 입력이 필요 없는 기능부터 만들면 **빨리 눈에 보이는 결과**가 나와서 진행이 잘 된다.

## 6. 개인 데이터 저장 결정

생년월일·꿈 일기는 **브라우저 localStorage에만**. 회원가입·서버 저장 없음 → 개인정보 부담 0. 대신 꿈 일기는 JSON **내보내기/가져오기**로 백업.

## 정리
- 기능 목록보다 먼저 **데이터 출처**를 정한다
- 우선순위는 "빨리 보이는 것"부터
- 개인정보는 안 모으는 게 최고의 보안
